# Introduction to Playwright

## 1. Introduction to Playwright

### 1.1 What is Playwright?

Playwright is an open-source browser automation and end-to-end testing framework developed by Microsoft.

It allows developers and testers to automate browser interactions programmatically using languages such as Python, JavaScript, TypeScript, Java and .NET.

Playwright can interact with web applications just like a real user by navigating between pages, clicking buttons, entering text, selecting options, uploading files and validating application behaviour.

It supports three major browser engines:

- **Chromium** – Used by browsers such as Google Chrome and Microsoft Edge.
- **Firefox** – Mozilla Firefox browser engine.
- **WebKit** – Browser engine used by Safari.

### 1.2 What is Browser Automation?

Browser automation is the process of controlling a web browser programmatically to perform actions that would otherwise require manual interaction.

Instead of manually opening a website, entering credentials, navigating through pages and checking results, an automation script performs these activities automatically.

#### 1.2.1 Common Browser Automation Activities

- Opening and navigating to websites.
- Clicking buttons, links and other interactive elements.
- Entering text into input fields.
- Selecting options from dropdown menus.
- Checking and unchecking checkboxes.
- Submitting forms.
- Validating text, messages and application elements.
- Uploading and downloading files.
- Handling browser tabs, windows, frames and dialogs.
- Capturing screenshots and recording test traces.

#### 1.2.2 What Can Playwright Automate?

Playwright is primarily designed for browser automation, but it also provides capabilities for API testing, network handling and mobile browser emulation.

**7. API Testing**

Playwright provides `APIRequestContext` to send HTTP requests and validate API responses independently of browser interactions.

**9. Mobile Browser Testing**

Playwright supports mobile device emulation, including:

**Important Limitation**

Playwright is not a general-purpose desktop or native mobile automation framework. It does not directly automate native Windows desktop applications or native Android and iOS applications through their native interfaces.

It can, however, automate websites and web applications accessed through mobile browsers using device emulation.

#### 1.2.3 Example: Basic Browser Automation

The following example demonstrates how Playwright opens a browser, navigates to a website, retrieves the page title and closes the browser.

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:

    browser = p.chromium.launch(headless=False)

    page = browser.new_page()

    page.goto("https://www.google.com")

    print(page.title())

    browser.close()
```

**Code Explanation**

| Code | Description |
|---|---|
| `sync_playwright()` | Initializes the synchronous Playwright API. |
| `p.chromium.launch()` | Launches a Chromium browser instance. |
| `headless=False` | Opens the browser in visible mode. |
| `browser.new_page()` | Creates a new page using a new browser context. |
| `page.goto()` | Navigates to the specified URL. |
| `page.title()` | Retrieves the current page title. |
| `browser.close()` | Closes the browser instance. |

### 2. Features of Playwright

**1. Cross-Browser Support**

Playwright supports Chromium, Firefox and WebKit, allowing tests to run across different browser engines.

**2. Auto-Waiting**

Playwright automatically waits for elements to satisfy the necessary actionability conditions before performing actions such as clicking.

**3. Web-First Assertions**

Playwright provides assertions that automatically retry until the expected condition is satisfied or the timeout is reached.

**4. Multiple Browser Contexts**

Browser contexts allow independent browser sessions within the same browser instance.

**5. Parallel Test Execution**

Playwright can execute tests in parallel when integrated with suitable test runners such as pytest.

**6. Network Interception**

Playwright can monitor, intercept and modify network requests and responses.

**7. Screenshots and Video Recording**

Playwright supports capturing screenshots and recording videos for debugging and reporting.

**8. Trace Viewer**

Playwright provides a Trace Viewer to inspect test execution, actions, DOM snapshots, network activity and other debugging information.

**9. Headless and Headed Execution**

- Headless mode: Executes the browser without displaying its graphical interface.
- Headed mode: Executes the browser with its graphical interface visible.

**10. Synchronous and Asynchronous APIs**

Playwright for Python provides both synchronous and asynchronous APIs.

### 3. Playwright and pytest

Playwright is a browser automation library, whereas pytest is a Python testing framework.

They serve different purposes and can be integrated to build automated testing frameworks.

| Playwright | pytest |
|---|---|
| Automates browser interactions. | Executes and manages test cases. |
| Provides browser automation APIs. | Provides test discovery and execution. |
| Interacts with web elements. | Provides fixtures and test setup. |
| Supports browser assertions. | Provides test organization and reporting integrations. |
| Handles browser operations. | Manages test execution and results. |

**Why Use Playwright with pytest?**

- Organizing test cases into separate files.
- Reusing browser setup through fixtures.
- Managing test execution.
- Supporting parametrized tests.
- Running tests in parallel using plugins.
- Generating test reports through reporting plugins.

### 4. Basic Playwright Test Using pytest

**Example:**

```python
from playwright.sync_api import Page, expect

def test_homepage(page: Page):

    page.goto("https://www.google.com")

    expect(page).to_have_title("Google")
```

**Code Explanation**

| Code | Description |
|---|---|
| `Page` | Type annotation representing a Playwright page. |
| `expect` | Provides Playwright assertions. |
| `test_homepage()` | A pytest test function. |
| `page` | Browser page fixture provided by the pytest-playwright plugin. |
| `page.goto()` | Navigates to the specified website. |
| `expect(page).to_have_title()` | Validates the page title. |

**Execution Command:**

```bash
python -m pytest test_playwright_intro.py
```

The `pytest-playwright` plugin provides fixtures such as `page`, `context` and `browser` for use in pytest test cases.

### 5. Important Playwright Objects

| Object | Description |
|---|---|
| Playwright | Entry point for accessing Playwright browser automation functionality. |
| BrowserType | Represents a browser engine such as Chromium, Firefox or WebKit. |
| Browser | Represents a launched browser instance. |
| BrowserContext | Represents an isolated browser session. |
| Page | Represents an individual browser tab or page. |
| Locator | Represents a way to find and interact with DOM elements. |
| Frame | Represents a frame within a page. |
| Download | Represents a file download. |
| Request | Represents a network request. |
| Response | Represents a network response. |

### 6. Playwright Automation Workflow

A typical browser automation workflow follows these steps:

1. Initialize Playwright.
2. Launch the required browser.
3. Create a browser context.
4. Open a new page.
5. Navigate to the application.
6. Locate web elements.
7. Perform user interactions.
8. Validate expected results.
9. Capture debugging information when required.
10. Close the browser.

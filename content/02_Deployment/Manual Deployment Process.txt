# VTPL-079 – Manual Deployment Process

## 1. Pre-Deployment Preparation and Patch Creation

### 1.1 Navigate to the Deployment Network Path

- Navigate to the network path where the deployment files are provided.
- Open the deployment folder corresponding to the required UI/UX version and target server.

**Example Network Path:**

```text
\\vtplsvr03\F\InternalRelease\UI-UX-9.1.1.6\Allusers\UIUX-CPS\11-Nov-2026-UIUX Consolidate Scripts and Files for vtpl-079
```

### 1.2 Locate and Update Flags.ini

- Navigate to the `Server` folder within the deployment directory.
- Copy and paste the provided `Flags.ini` file into the `Server` folder.
- Open Windows Registry Editor (`regedit`).
- Navigate to the following registry path:

**Registry Path:**

```text
Computer\HKEY_LOCAL_MACHINE\SOFTWARE\WOW6432Node\Vicisoft\ViciDocs\1.0\Params
```

**Important:**

- This registry path is applicable only for Manual Deployment.
- Do not use this registry path as a reference for Auto-Deployment.
- Locate the `previousVersionInstalled` value in the registry.
- Note down the existing version number.

### 1.3 Update Version Details in Flags.ini

- Return to the `Flags.ini` file located in the `Server` folder.
- Update the version details using the value obtained from the Registry Editor.

Follow the below logic:

- **Previous Version:** Set this value to the existing `previousVersionInstalled` value obtained from the registry.
- **Current Version:** Set this value to the previous version number + 1, following the applicable versioning convention.

**Example:**

If the registry value is `9.1.1.5`:

```ini
Previous Version = 9.1.1.5
Current Version  = 9.1.1.6
```

- Save the updated `Flags.ini` file.

### 1.4 Select the Required Application Folders

- Navigate to the `Server` folder.
- Identify the application folders required for the deployment package.
- Select all relevant server-side application folders.
- Do not select folders containing `CLIENT` in their names.
- Ensure that only the required server-side application folders are selected.

**Examples of relevant folders:**

- `docmanager`
- `WebApp`
- `WebAPPAD`
- `Shareddotnetdll`
- Other relevant server-side application folders provided in the deployment package.

### 1.5 Create the ViciECMPatch.zip File

- After selecting the required application folders, create a ZIP archive containing the selected folders.
- Name the ZIP archive exactly:

```text
ViciECMPatch.zip
```

- Verify that the ZIP archive contains all the required application folders.
- Ensure that folders containing `CLIENT` in their names are excluded.

### 1.6 Share Deployment Files with the Manual Deployment Team

- Share the network path containing the deployment files and the newly created `ViciECMPatch.zip` file with the Manual Deployment team.
- The Manual Deployment team will use the provided files to create the deployment patch.
- Wait until the Manual Deployment team releases the final application patch (`.exe` file).

---

## 2. Collect the Released Patch and Prepare the Local Deployment Directory

### 2.1 Collect the Released Patch and Database Scripts

- Once the Manual Deployment team releases the patch, navigate to the same network path shared earlier.
- Locate the `Database` folder.
- Identify and collect all relevant database scripts required for the deployment.

The required database scripts cover two database levels:

1. **Repository Level:** Scripts related to the `VICIECMSS` database.
2. **RPDocMgrDB Level:** Scripts related to the `RpDOCmgr` database.

**Important:**

Since VTPL-079 is connected to the SQL Server, collect only the required scripts from the `SQL` folder.

### 2.2 Create the Local Deployment Directory in the VTPL-079 Server

- Access the VTPL-079 server.
- Navigate to:

```text
C:\Updates\
```

- Create a new folder using the current deployment date.

**Example:**

```text
C:\Updates\11-11-2026\
```

- Inside the newly created date-wise folder, create a `Database` folder.

### 2.3 Copy Database Scripts

- Copy the required Repository Level database scripts from the released deployment files.
- Ensure that the Repository Level scripts are placed inside the Repository Level folder.
- Copy the required RPDocMgrDB Level database scripts.
- Paste the scripts into the following directory:

```text
C:\Updates\11-11-2026\Database\
```

- Ensure that the RPDocMgrDB scripts are placed inside the `RPDocMgrDB` folder.

**Script Locations:**

```text
C:\Updates\11-11-2026\Database\RPDocMgrDB\

C:\Updates\11-11-2026\Database\Repository_Level\
```

- Verify that all required database scripts are available.

### 2.4 Copy Configuration Files and Application Patch

- Collect the configuration files provided with the deployment package.
- Copy and paste all required configuration files into the date-wise deployment folder.

**Destination:**

```text
C:\Updates\11-11-2026\
```

- Copy the final application patch released by the Manual Deployment team.
- Paste it into the same date-wise deployment folder.

**Application Patch Name:**

```text
ViciECMPatch.exe
```

### 2.5 Verify the Deployment Directory

Before proceeding, verify that the following items are available:

- Repository Level database scripts.
- RPDocMgrDB Level database scripts.
- Required configuration files.
- Application patch (`ViciECMPatch.exe`).

**Expected Directory Structure:**

```text
C:\Updates\
    |
    └── 11-11-2026\
        |
        ├── Database\
        |   |
        |   ├── RPDocMgrDB\
        |   |   ├── Database Script 1
        |   |   ├── Database Script 2
        |   |   └── Remaining RP Scripts
        |   |
        |   └── Repository_Level\
        |       ├── Database Script 1
        |       ├── Database Script 2
        |       └── Remaining Repository Scripts
        |
        ├── Configuration Files
        |
        └── ViciECMPatch.exe
```

- Ensure that all required files have been copied successfully.
- Verify that the local deployment directory is ready for deployment.

## 3. Stop Services and Prepare the Server

### 3.1 Stop ViciECM Application Services

- Access the VTPL-079 server.
- Open the Windows Services console.

```text
services.msc
```

- Identify all services related to ViciECM.
- Stop all relevant ViciECM application services.
- Verify that the services have stopped successfully.

### 3.2 Stop IIS

- Open Command Prompt with Administrator privileges.
- Execute the following command:

```cmd
iisreset -stop
```

- Wait until the command confirms that Internet services have stopped successfully.
- Verify that IIS has stopped.

### 3.3 Unregister DocManager Components

- Navigate to the DocManager installation directory.
- Locate `DOCMANAGER.exe`.
- Right-click the file and select **Copy as path** to obtain its location.
- Open Command Prompt as Administrator.
- Navigate to the DocManager directory.

**Example:**

```cmd
cd C:\ViciECM\DocManager-64bit
```

- Execute the following command to unregister DocManager:

```cmd
DOCMANAGER.exe /unregserver
```

- Check whether `DocManagerps.dll` exists in the same directory.
- If the DLL exists, execute the following command to unregister it:

```cmd
regsvr32 /u DocManagerps.dll
```

**Note:**

- DLL unregistration is conditional on the file being present.
- Verify that the unregistration operation completes successfully.

---

## 4. Execute the Application Patch

### 4.1 Launch the Deployment Package

- Navigate to the local deployment directory:

```text
C:\Updates\11-11-2026\
```

- Locate and launch `ViciECMPatch.exe`.
- Allow the deployment package to initialize.

### 4.2 Perform Incremental Backup

- When prompted, select the `Incremental Backup` option.
- Allow the backup process to begin.
- Wait until the backup process completes.
- Once completed, click **OK** to proceed.

### 4.3 Extract Application Patch Files

- After confirming the backup, the patch extraction process will begin automatically.
- Allow the extraction process to continue.
- Verify that the application patch files are being extracted.

**Note:** While the extraction process is running, proceed with the next deployment step.

---

## 5. Execute Database Scripts

### 5.1 Open SQL Server Management Studio

- Launch SQL Server Management Studio (SSMS).
- Connect to the SQL Server instance associated with VTPL-079.
- Enter the required SQL Server credentials.
- Verify that the connection is established successfully.

### 5.2 Execute RPDocMgrDB-Level Scripts

- Navigate to the following directory:

```text
C:\Updates\11-11-2026\Database\RPDocMgrDB\
```

- In SSMS, locate the `RpDOCmgr` database under **Databases**.
- Right-click the database and select **New Query**, or use the keyboard shortcut:

```text
Ctrl + N
```

- Open the first required database script from the local deployment directory.
- Copy its contents and paste them into the SQL Query Editor.
- Click **Execute**.
- Verify that the script executes successfully.
- Clear the existing query or open a new query window using `Ctrl + N`.
- Copy and paste the second script.
- Execute it and verify the result.
- Repeat the same procedure until all required RPDocMgrDB scripts have been executed.

**Execution Sequence:**

1. Select the `RpDOCmgr` database.
2. Open a new query.
3. Copy and paste the first script.
4. Click Execute.
5. Verify the execution result.
6. Clear the query or open a new query.
7. Repeat the process for the remaining scripts.

### 5.3 Execute Repository-Level Scripts

- In SSMS, select the `ViciECMSS` database.
- Right-click the database and select **New Query**, or use `Ctrl + N`.
- Navigate to the Repository Level scripts in:

```text
C:\Updates\11-11-2026\Database\Repository_Level\
```

- Copy the first required Repository Level script and paste it into the SQL Query Editor.
- Click **Execute**.
- Verify successful execution.
- Clear the existing query or open a new query window.
- Copy and execute the next script.
- Repeat the procedure until all required Repository Level scripts have been executed.

**Execution Sequence:**

1. Select the `ViciECMSS` database.
2. Open a new query.
3. Copy and paste the first script.
4. Click Execute.
5. Verify the execution result.
6. Clear the query or open a new query.
7. Repeat the process for the remaining scripts.

### 5.4 Verify Database Script Execution

- Verify that all RPDocMgrDB-level scripts have executed successfully.
- Verify that all Repository-level scripts have executed successfully.
- Check the execution results for errors before proceeding.
- Follow the prescribed script execution order.
- Ensure that all required database scripts have been executed.

**Important:**

- Execute the scripts against the correct databases.
- Do not skip any required scripts.
- Do not proceed to the next script without checking the previous execution result.
- If a script fails, report the error and follow the approved resolution procedure before continuing.

## 6. Handle Deployment Errors and Register DocManager Components

### 6.1 Handle Deployment Errors

**Important:** The `ViciECMPatch.exe` process may fail to complete if relevant application services or Task Scheduler-related processes are still running.

If deployment errors occur:

- Open the Windows Services console.
- Identify and stop the relevant ViciECM services.
- Open Task Manager and disable any ViciECM-related scheduler that is enabled.
- Open **Task Manager > Details**.
- Identify the deployment-related processes that are still running.
- Check for running Task Scheduler-related processes and terminate the corresponding processes where necessary.
- Retry the patch execution after ensuring that the required services and processes have stopped.

**Important:** Do not terminate unrelated Windows processes or services.

### 6.2 Register DOCMANAGER.exe

- Open Command Prompt with Administrator privileges.
- Navigate to the DocManager installation directory.

```cmd
cd C:\ViciECM\DocManager-64bit
```

- Execute the following command to register DocManager:

```cmd
DOCMANAGER.exe /regserver
```

- Verify that the registration command completes successfully.

### 6.3 Register DocManagerps.dll

- Check whether `DocManagerps.dll` exists in the DocManager installation directory.
- If the DLL exists, execute:

```cmd
regsvr32 DocManagerps.dll
```

- Verify that the registration completes successfully.

**Expected Result:**

A successful registration confirmation message should appear.

### 6.4 Execute the DCOM Batch File

- Navigate to the relevant file location provided with the deployment package.
- Locate the `Dcom.bat` file.
- Execute `Dcom.bat` as required by the deployment instructions.
- Verify that the execution completes successfully.

- Open the Windows Services console.

- Start all the required services.

- Verify that all required services are running successfully.

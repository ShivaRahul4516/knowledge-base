
# Manual Deployment Process

## 1. Basics

### 1.1 What is Deployment?
- Applying changes to an existing application using Patch / Build Files is called Deployment.

### 1.2 What is Services Application?
- It is an application that displays a list of all the programs that actually run in the background.
- Press `Win + R` and type `services.msc` to open the Services window.

### 1.3 What is a Patch?
- A targeted fix of a bug can be called a Patch.

### 1.4 What is a Server and a Client?
- A computer providing services to other computers is called a Server.
- It receives requests from clients, processes those requests, and sends back a response.
- The Client's request is usually sent to the Application Server, which requests the necessary data from the Database Server.
- The Database Server sends the data to the Application Server, and the Application Server sends the data back to the Client.
- When accessing Google Chrome, the browser can act as a Client.
- An application requesting services from a server is called a Client.

### 1.5 What is an Environment?
- A setup where an application is installed and running for a particular purpose, with a particular version of the application.

#### Types of Environments
- DEV → Development
- QA → Testing
- UAT → User Acceptance
- PROD → Live / Production Use

## 2. Deployment Process

### 2.1 Stop the Required Services
- Press `Win + R`.
- Type `services.msc`.
- Stop the following services:
  - Text Extraction
  - Format Converter
  - Doc Manager
  - Workflow Escalation

### 2.2 Download the Patch Files
- In the Support Repository, the team will create a job with the required files attached.
- Log in as the assigned user and download the attached files.

### 2.3 Prepare the Deployment Folder
- Press `Win + R`.
- Enter the shared path.
- Run the batch file, which creates the required folder structure with the current date.
- Log in to the Support Repository.
- Navigate to `Workflow → My Jobs → Process → Attachments`.
- Download the necessary files.
- Move or paste the files into their respective folders.

### 2.4 Execute the Patch
- Run the Patch.
- Select Incremental Backup.
- This automatically creates a folder with the current date.
- The Full Backup option takes too much time.

### 2.5 Update Deployment Documentation
- Update the Bugs List file.
- Rename the Excel file using the assignee's name.

### 2.6 Restart Services and Verify the Application
- Once the patch work is completed, start the services again.
- Try logging in to the application.

### 2.7 Rollback Procedure
- If you are unable to log in to the application, you can use the rollback script with the Team Lead's permission.
